WHY THIS IS FULL COUNTING

The input `gap` says that F restricted to im(F) omits one of that range's
members. The readback equation is:

  (F(Fx))T = Fx, for every x.

The inherited JJ203Range argument, restated against the uploaded CountSet API
in CountingCalibration.lean, makes d=im(F) into a strongly Cantorian set with
an internally represented proper self-injection. The uploaded theorem
FNF.T_eq_of_strong_dedekind proves T(n)=n for every internal Frege natural
number; FNF.counting_of_T and FNF.countChurch_iff_counting identify this with
Rosser Counting and the FunctionNF counting sentence. This does not merely
check each externally standard numeral.

THE TWO DIRECTIONS AND THEIR REMAINING OBLIGATIONS

1. No numerical proof of the designated false goal implies Consistent(NFC).

   The release's quotient construction supplies the extensional application,
   K/B basis and variable tester. Four separating arguments give the arbitrary
   Boolean basis on that same application. The release's algebra establishes
   readback and a proper range map. The uploaded proof body now supplies the
   full-counting-to-pure-NF consistency endpoint without the old v15 theorem
   being left as an external manuscript premise.

   The particular quotient, tester conversion and generated numerical emitter
   are still inherited parts of the machine proof. The new adapter source
   connects their explicit mathematical outputs; it is not an end-to-end
   kernel replay of those constructions.

2. Consistent(NFC) implies no numerical proof of the false goal.

   The uploaded NFC-to-FNFC interpretation provides a counted function model.
   However, the machine requires the additional designated equations
   TT=F and FT=B, with T as its variable tester, while preserving the native
   B law and the unconditional readback equation. The release's special
   full-chart construction in Staged_Counting_Calculus.md builds those rows.
   The uploaded NFC-to-FNFC theorem does not state those extra properties.
   That chart construction remains a written mathematical obligation.

3. The binary table detects exactly a numerical goal proof.

   Physical trace/kernel certificates and blank startup concern the compiled
   register program. Row soundness, row reachability, finite proof-word
   construction and eventual occurrence in the integer enumeration are
   distinct logical/source obligations. Census_transfer.md and the inherited
   source_argument.md and MarkerProof.md give written arguments. The actual
   184-to-183 source edit is only a register permutation; it preserves the
   row order, formulas and control-flow tree. Its authenticating rebuild
   therefore transports the existing indexed extraction argument directly.

CHANGING THE BLANK START FROM ENUMERATION COUNTER 3 TO 1

The proposed 183-state backend reaches PC zero with enumeration counter 1
and all eight other registers zero. Provided the source register permutation
has been authenticated, the inherited enumeration proof applies.

MarkerProof.md does not require the initial counter to be 3. It chooses the
three-epoch synchronization window ending at n=P(K,z+1), with K greater than
the starting epoch, and permits any fixed initial rank r0. The marker bound
uses r0+(n+2)^2+1 and can always be met by increasing K. Every command has
finitely many batches and decreases its remaining cursor at continuation;
hence each preceding epoch terminates unless the machine has already halted.
The fresh counter then advances through all sufficiently large integers.

Starting at 1 therefore inserts two finite earlier epochs. Source soundness
applies from the zero proof payload and is preserved by every emitted axiom,
stack operation and matching detachment, so an earlier stop still witnesses
a genuine numerical proof. If no earlier stop occurs, an arbitrarily late
synchronizing window is eventually reached, exactly as for start 3.

This is a written cofinal-enumeration transfer, independent of the physical
boot certificate. It does not assert a freshly checked Lean theorem for the
complete stream. The canonical PC-zero entry and zero scratch registers must
be supplied by the new physical certificate; the counting theory calibration
then retains the qualifications stated above.

TARGETED REVIEW OF THE NEW KERNEL WRAPPER

The source permutation maps old logical register zero to physical register
one. Changing kernel_branches.py from runs[0] to runs[discover.COUNTER] in
the cold-counter branch is therefore the required change, and the symbolic
trace generator uses the same parameter. The check_all.py coverage formula
also reads COUNTER_ROLE, while verify.py supplies COUNTER_ROLE=1. A stale
register-zero exclusion was found in the optional check_persisted.py wrapper
and reported to the compiler owner, who corrected it. This was a replay
wrapper defect; the active check_all replay already used the correct index.
